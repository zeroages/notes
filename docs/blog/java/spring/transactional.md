@Transactional注解

Spring 声明式事务（`@Transactional`）失效，根源大多在于**Spring 事务是基于 AOP（面向切面编程）代理实现的**。一旦代理机制无法正常工作，事务自然就失效了。

下面是几类最常见的失效场景及解决方案。

| 失效场景 | 核心原因 | 解决方案 |
| :--- | :--- | :--- |
| **方法非 `public`** | 代理无法应用 | 改为 `public` 方法 |
| **同类方法自调用** | 调用绕过代理 | 注入自身、`AopContext.currentProxy()` 或拆分到不同类 |
| **方法为 `final`** | 代理（CGLIB）无法继承 | 移除 `final` 修饰符 |
| **类未被 Spring 管理** | 无代理对象 | 添加 `@Service` 等注解 |
| **异常被 `try-catch` 吞掉** | Spring 未感知到异常 | 重新抛出异常，或不捕获 |
| **异常类型不匹配** | 默认只回滚运行时异常 | 指定 `rollbackFor = Exception.class` |
| **数据库引擎不支持** | 数据库层不支持 | 改用 InnoDB 等支持事务的引擎 |
| **未配置事务管理器** | 缺少事务管理核心组件 | 配置 `PlatformTransactionManager` |
| **多线程调用** | 事务上下文不共享 | 避免跨线程的事务操作，或使用编程式事务 |

了解这些常见陷阱后，排查事务问题会更有方向。如果遇到具体问题，可以优先检查方法是否为 `public`，以及是否存在自调用或异常被吞的情况。
